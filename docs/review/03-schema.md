# 03 — Schema translation (`com.evolveum.polygon.connector.ldap.schema`)

This package does the real work of the connector: `AbstractSchemaTranslator` builds the ConnId schema from the
server's LDAP schema, converts every entry into a `ConnectorObject` and every ConnId value back into an LDAP
`Value`; `LdapFilterTranslator` turns ConnId filters into Directory-API filter nodes. The read path is generally
careful — it decides by syntax OID first and falls back to the Directory API's human-readable flag — but the write
path is not symmetric with it, and the newer association/reference code (`ReferenceAttributeTranslator`,
`saturateConnIdReferences`, `constructAssociationSets`) is noticeably less defensive than the surrounding code:
it dereferences values that its own callers document as nullable, and it re-does per-attribute work per value.
The two blockers below are both in that read/write asymmetry: binary values are silently stringified when they are
written back, and reading a group's members is quadratic in the number of members. Filter escaping itself is *not*
a problem — every value goes through `Value`/`EqualityNode`/`SubstringNode`, which the Directory API encodes and
escapes for us, so there is no injection path; the filter risks here are null `AttributeType`s and one shadowed
overload with the wrong semantics. `GuardedStringValue` never holds plaintext (it stores the `GuardedString` and
lets `Value` hold `GuardedString.toString()`, which ConnId does not override, i.e. an identity hash) — but
`hashLdapPassword` right next to it does copy the cleartext into an immutable `String` that is never cleared.

## Findings

- `blocker` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/AbstractSchemaTranslator.java:869` | `wrapInLdapValueClass` branches on `isBinarySyntax(...)` at 844 and then on `!isBinarySyntax(...)` at 869, which makes the "detected binary" fallback at 894-912 unreachable; a `byte[]` value whose syntax is not in the seven hard-coded OIDs of `isBinarySyntax` therefore reaches line 872 and is written to the directory as `connIdAttributeValue.toString()`, i.e. the literal text `[B@1b6d3586`. This is live for eDirectory: `EDirectorySchemaTranslator.toConnIdType` declares Octet List (`2.16.840.1.113719.1.1.5.1.13`) and Replica Pointer (`…5.1.16`) as `byte[]`, but its `isBinarySyntax` override only adds NetAddress, so those attributes read back as `byte[]` and write back as garbage. | Replace the `else if (!isBinarySyntax(syntaxOid))` branch with the value-type test that the dead `else` already contains: check `connIdAttributeValue instanceof byte[]` first and only fall back to `toString()` for non-byte values.
- `blocker` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/AbstractSchemaTranslator.java:1627` | `saturateConnIdReferences` calls `handler.translate(ldapAttribute)` once *per value*, while `ReferenceAttributeTranslator.translate` itself iterates the whole attribute and adds all references to the `ConnectorObjectBuilder`; reading an attribute with N values allocates N² `ConnectorObjectReference`/`ConnectorObjectIdentification`/`Attribute` objects (`ConnectorObjectBuilder.addAttribute` keys by name, so only the last of the N identical attributes survives — all the rest is wasted). A 20 000-member eDirectory group means 4·10⁸ throw-away objects, so the search stalls or dies with `OutOfMemoryError`. | Call `handler.translate(ldapAttribute)` once, outside the value loop — the per-value `shouldValueBeIncluded` check is already duplicated inside `translate` at `ReferenceAttributeTranslator.java:111`, so the outer loop can be deleted entirely.
- `major` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/ReferenceAttributeTranslator.java:148` | `referenceAttributeName` is never null-checked before `attributeBuilder.setName(...)`, which throws `IllegalArgumentException("Name must not be blank")`, and `new ObjectClass(targetOcName)` at line 133 throws the same way; both trigger when no `AssociationHolder` matches, and a mismatch is easy to get because this class matches on the raw `ldapAttribute.getId()` (attribute options such as `;binary`/`;range=` are *not* stripped here, and the server may return an alias name) while `AbstractSchemaTranslator.isAssociationAttribute` matched on the schema's primary name from `getLdapAttributeName`. The result is an aborted search, not a skipped attribute. | Resolve the name with `translator.getLdapAttributeName(ldapAttribute)`, and log-and-return when `referenceAttributeName`/`targetOcName` stay null instead of building an unnamed attribute.
- `major` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/AbstractSchemaTranslator.java:1989` | `hashLdapPassword` copies the cleartext out of the `GuardedString` accessor into an immutable `String` (`out[0] = new String(clearChars)`) and then into a `byte[]`; neither is cleared, so with `passwordHashAlgorithm` configured every password change leaves the plaintext in the heap until GC — readable in any heap dump or core file — which defeats the whole point of the `GuardedStringValue` late-decryption design in the same package. | Do the hashing inside the `Accessor` callback: convert `clearChars` to bytes via `StandardCharsets.UTF_8.encode(CharBuffer.wrap(clearChars))`, feed the digest, and zero the byte array in a `finally`.
- `major` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/LdapFilterTranslator.java:441` | `schemaTranslator.toLdapAttribute` is documented (`AbstractSchemaTranslator.java:553-555`) to return null for legal-but-undefined attributes — it does so for `__NAME__` and for virtual reference attributes (`isVirtualAttribute`, which is true for `group` = `LdapConstants.ATTR_SCHEMA_SUBJECT` whenever `managedAssociationPairs` is set) — but the result goes straight into `EqualityNode` (441, 190, 196), `PresenceNode` (154, 437) and `SubstringNode` (235-241, 265), whose shared `LeafNode(AttributeType, AssertionType)` constructor throws `NullPointerException` on a null type. Any search filtered by the association reference attribute dies with a bare NPE from the Directory API. | Null-check the returned `AttributeType` in each translate method and throw `InvalidAttributeValueException` naming the ConnId attribute (or handle reference attributes explicitly before the lookup).
- `major` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/LdapFilterTranslator.java:250` | The public overload `translate(EqualsFilter)` translates equality into a prefix `SubstringNode` (line 265) and rejects `__NAME__` with a "wildcard filter" message, contradicting the live `translateEqualsFilter` that the dispatcher at line 392 actually uses; it is unused today, but it sits in a class full of `translate(XxxFilter)` overloads, so Java overload resolution silently picks it for any caller or subclass holding a statically-typed `EqualsFilter` — turning `cn = "jack"` into `(cn=jack*)` and returning wrong objects for identifier/correlation lookups. | Delete the method, or make its body `return translateEqualsFilter(connIdFilter);`.
- `major` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/AbstractSchemaTranslator.java:1944` | `processObjectClasses` adds the *entire* `outstandingObjectClasses` list once per element that passes the three `hasSubclass` guards above it, so with `alternativeObjectClassDetection` enabled those guards are pointless (excluded classes are added anyway) and the auxiliary list gets n copies of every class, producing duplicate `__AUXILIARY_OBJECT_CLASS__` values on every converted object. | Use `ocs.getLdapAuxiliaryObjectClasses().add(objectClass)` — the loop variable — instead of `addAll(outstandingObjectClasses)`.
- `minor` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/AbstractSchemaTranslator.java:662` | `toConnIdType` looks `SYNTAX_MAP` up by `syntax.getName()` while `toConnIdSubtype` (699/706) and `isSyntaxOfClass` (1080) look it up by OID; it only works because RFC 4512 syntax descriptions carry no NAME and `AbstractSchemaObject.getName()` falls back to the OID. The one genuinely name-keyed entry, `addToSyntaxMap("OctetString", byte[].class)` at 2583, is consequently invisible to `isBinarySyntax`/`isTimeSyntax`, so such an attribute is published as `byte[]` but converted as a string. | Key and query the map by OID only (`SYNTAX_MAP.get(syntax.getOid())`) and drop or re-key the `"OctetString"` entry.
- `minor` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/AbstractSchemaTranslator.java:2209` | `determineAttributesToGet` passes `options` to `getStandardObjectClassAttributes`, which dereferences it at line 2300 (`options.getAttributesToGet()`), four lines *before* its own `options == null` guard at 2213 — so the documented null-tolerance is a lie and any caller that takes it at face value gets an NPE instead of the "all attributes" default. | Move the null handling above line 2209, or read the attrs-to-get as `options == null ? null : options.getAttributesToGet()` inside `getStandardObjectClassAttributes`.
- `minor` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/AbstractSchemaTranslator.java:962` | The guard that is supposed to report "More than one value specified" builds its message with `ldapAttributeType.getName()`, but the same method accepts a null `ldapAttributeType` two lines below (`toLdapValue` handles it) — a multi-valued filter on an attribute with no definition therefore throws NPE from inside the error path and the real problem is never reported. | Use a null-safe name in the message (fall back to the ConnId attribute name passed by the caller).
- `minor` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/AbstractSchemaTranslator.java:885` | The inner `catch (LdapInvalidAttributeValueException ex)` of the `encodeStringOnNormalizationFailure` retry rethrows with `e` (the original normalization failure) as both message source and cause, discarding `ex`; when the UTF-8 byte fallback fails, the exception that explains why is lost and the log shows the first, already-handled error. | Build the message from `ex` and chain `ex` as the cause.
- `minor` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/AbstractSchemaTranslator.java:1794` | `shouldValueBeIncluded` — called once per attribute value during entry conversion — writes back into the shared, pooled configuration object (`configuration.setMemberOfAllowedValues(...)`), so the connector silently rewrites a configuration property the admin never set; and when `baseContext` is unset (it is optional, `AbstractLdapConfiguration.validate` only checks it when non-null, and `searchByDn` works without it) the resulting `new String[]{null}` makes `Predicate.not(String::isEmpty)` throw NPE on the next `memberOf` value. | Compute the fallback into a local variable and skip null/blank entries; do not mutate the configuration from a conversion path.
- `minor` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/AbstractSchemaTranslator.java:2612` | `getObjectAssociationSets()`/`getSubjectAssociationSets()` return **null** for the default configuration (`managedAssociationPairs` defaults to `{}`, so `constructAssociationSets` leaves both fields null) and re-run the construction loop on every call whenever the map is null or empty; the lazy init is also unsynchronized, so two concurrent searches can both enter `constructAssociationSets`. Every existing caller happens to guard with `ArrayUtils.isEmpty(getManagedAssociationPairs())`; the next one will NPE. | Build the maps once (constructor or a synchronized one-shot flag) and return `Collections.emptyMap()` when no pairs are configured.
- `minor` | `src/main/java/com/evolveum/polygon/connector/ldap/schema/AbstractSchemaTranslator.java:1190` | In `isBinaryAttribute` the `STRING_ATTRIBUTE_NAMES` lookup has no effect — both it and the fall-through at 1196 `return false`, so the hard-coded root-DSE string list (2588-2608) only suppresses a log warning while reading as if it drove the decision; the lookup also uses the un-stripped `attributeId` and a locale-sensitive `toLowerCase()`, so it misses `namingContexts;x` and, under a Turkish default locale, `isSynchronized`. | Either delete the list and the branch, or make it meaningful (and use `ldapAttributeName.toLowerCase(Locale.ROOT)`).

No further blocker-level findings. `SystemSchemaLoader`, `ScopedFilter`, `LdapObjectClasses`, `AssociationHolder`
and `AttributeHandler` produced nothing worth reporting; note only that `AssociationHolder` is stored in `HashSet`s
while `saturateAssociationHolders` mutates `isRequired`, which is part of its `hashCode` — harmless today because
nothing looks the holders up after mutation, but it makes the sets unsafe for `contains`/`remove`.
