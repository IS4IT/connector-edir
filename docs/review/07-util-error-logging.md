# Unit 07 — shared utilities, error mapping, logging façades

`LdapUtil`, `ErrorHandler`, `ConnectionLog`, `OperationLog`, `ConnectorBinaryAttributeDetector`, `ReconnectException`, `package-info`.

The DN comparison helpers (`isDescendantOf` / `equalsRdn` / `equalAva`) are correct — the suffix walk indexes both DNs from the least-significant end and handles multi-valued RDNs order-independently. Generalized-time conversion round-trips through `GeneralizedTime` correctly and reports parse failures as `InvalidAttributeValueException` with the entry DN. `formatLdapMessage` / `sanitizeString` are safe against a null diagnostic message in practice: the Apache codec's `StoreErrorMessage` action always sets at least `""`, and the connector never builds an `LdapResult` itself. `ConnectorBinaryAttributeDetector` is correct — the `null` translator fallback only applies before the schema is fetched, where every attribute really is a string, and the detector is re-used per `ServerConnectionPool` after `setSchemaTranslator`. `ConnectionLog` itself leaks nothing sensitive (host/port, base, scope, filter, DN only — no bind DN, no credentials) and gates every method on a level check before building the message. `OperationLog` does not: it is a pass-through with no redaction, and one call site feeds it a decrypted entry. The remaining defects cluster in log-message plumbing (wrong `MessageFormat` indexes, wrong log level, inverted null branches) and in a handful of result-code mappings that will mislabel routine eDirectory failures.
